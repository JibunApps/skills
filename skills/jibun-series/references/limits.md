# 制限事項と設計上の落とし穴

出典: 公式マニュアル「制限事項について」「運用・動作環境」（2026-09 時点）。

## kintone API 由来の制限

| 制限 | 内容 | 設計への影響 |
|---|---|---|
| 同時アクセス数 | kintone 環境全体で数秒間に 100 件超の同時 API アクセスは不可。読込中が続き、管理者にエラー通知 | イベント受付・月末一斉操作などピークが読める用途では、**ルックアップと添付ファイルをフォームに含めない**。ページでも一斉操作の時間帯を分散する |
| 1 日の API リクエスト数 | 1 アプリあたり 10,000 件／日（じぶんシリーズ公式マニュアル記載値）。超過時は cybozu から警告メール（即停止はしない）。※kintone 公式ヘルプは現在「契約コースによって上限値は異なります」と記載（ https://jp.kintone.help/k/ja/admin/limitation/limit ） | 利用者数×操作回数を見積もる。上限値は顧客の契約コースで確認。連日超過するなら cybozu に相談 |
| Webhook | **ドメイン単位**で 1 分 60 回まで（アプリ単位ではない）。61 回目以降は無視され、じぶん側で検知できない（出典: https://jp.kintone.help/k/ja/app/set_webhook/webhook ） | 複数アプリを連携している環境では合算で上限に当たる。レコード一括登録時に、レコード URL 自動作成や通知が抜ける可能性がある |

## フォーム送信が同時アクセス制限に当たったとき

- 利用者には送信完了画面が出るが、**kintone にはデータが入らず、自動返信メールも送られない**。
- 送信内容はじぶんフォーム管理画面（アプリ設定画面下部の「保存に失敗したデータ一覧」）に **エラーデータ** として保存され
  （`[GAIA_TO04] APIの同時リクエスト数が上限を超えています`）、
  管理者のメールアドレスに通知される。CSV でダウンロードして kintone に一括読み込みし、返信は手動で行う。
- エラーデータは削除しない場合 **30 日後に自動削除** される。復旧はこの期限内に行う（出典: https://www.jibun-apps.jp/jibun-page/faq/data_storage_location/ ）。
- この運用手順を、集中アクセスが見込まれるフォームの利用者（管理者）に事前に伝える。

## その他の制限

- 添付ファイルは 1 ファイル 30MB まで。拡張子は kintone に準じる。
- kintone アプリ更新後にじぶん側の同期を忘れると、新フィールドが出ない・保存に失敗する。
- kintone に IP アドレス制限がある環境は、IP アドレス制限対応オプション無しでは動かない。
- 「ユーザーに見せられるレコード条件」を未設定のじぶんページは **全レコードが見える**。外部公開前に必ず確認する。
- じぶんレコードで「コメント表示と通知メールの設定」をオンにすると、そのレコードに付いた **全コメント（kintone ユーザー同士のやり取り含む）が利用者画面に表示される**。社内限定コメントがあるアプリではオフにする。
- 基盤は Google Firebase。中国からの利用は不可の可能性あり（VPN 検討）。Firebase または kintone の障害時は連動して停止する。
- セキュリティチェックシートは公開版（経産省様式）と Assured 対応。個別回答は原則不可。

## 運用情報（顧客に聞かれたとき）

- 稼働率目標 99.9%（5 分以上の停止をダウンタイムとして計上）。じぶんページは SLA 適用。
- 操作ログ保管 400 日、メール送信ログ 30 日。DB バックアップは 24 時間ごと・30 日保管。
- 通信は TLS、機密情報は暗号化保存。運営側は kintone 内データを閲覧しない。
- サポート: 問い合わせフォーム 24 時間受付・一次回答 2 営業日以内。電話は平日 10-12 / 13-17（緊急時のみ）。
- 出典: https://www.jibun-apps.jp/operation/
