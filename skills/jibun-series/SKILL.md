# じぶんシリーズ × kintone 構築ガイド

じぶんシリーズは、ソニックガーデンが提供する kintone 連携製品群。大きく 2 系統ある。

- **外部共有 SaaS**（じぶんページ／じぶんフォーム／じぶんレコード）: kintone REST API 経由で kintone アプリと接続し、
  **kintone アカウントを持たない人**に「見せる」「入力させる」「1レコードだけ共有する」を提供する。
- **じぶん kintone プラグイン**: kintone 標準機能の「あと一歩」を埋める 42 種のプラグインを定額・ユーザー数無制限で提供する。
  kintone を使う社内ユーザー向け。JavaScript カスタマイズの代替になる。

公式サイト: https://www.jibun-apps.jp/

## このスキルでできること・できないこと

- できる: 要件から製品を選ぶ、じぶんシリーズで動く kintone アプリ（フィールド構成）を設計する、
  管理画面での設定手順を人に案内する、制限事項を踏まえた設計レビューをする、
  標準機能で足りない要件に対して JavaScript カスタマイズの代わりにプラグインを提案する。
- できない: じぶんシリーズの管理画面やプラグイン設定を API で操作すること（公開 API は無い）。
  じぶん側の設定は **人が管理画面で行う** 前提で、手順を提示する。

## 1. 製品選定（最初にやる）

| 要件 | 選ぶ製品 | 補足 |
|------|----------|------|
| 相手が **ログインして** 自分に関係する複数レコードを一覧・詳細・新規・編集する（マイページ） | **じぶんページ** | ユーザー招待制。ユーザー属性でレコードを絞り込む |
| 相手が **ログインせず** Web フォームから kintone にレコードを **新規登録** する | **じぶんフォーム** | 件数無制限。自動返信メール可 |
| 相手が **ログインせず** URL を開いて **特定の1レコード** を閲覧・編集・コメント・ファイル添付する | **じぶんレコード** | パスワード・公開終了日時を設定可 |
| フォームで受け付けた後、その案件のやり取りを続けたい | **フォーム ＋ レコード** | フォーム投稿時に自動でレコード URL を発行し、自動返信メールに載せる |

| 相手は **kintone を使う社内ユーザー** で、標準機能では届かない操作・表示・転記・通知をしたい | **じぶん kintone プラグイン** | JS カスタマイズを書く前に該当プラグインを確認する |

判断のコツ:

- 「相手ごとに見せるレコードが違う」「相手が繰り返しログインする」→ ページ。
- 「一回きりの受付」→ フォーム。「その後もやり取りする」→ フォームとレコードの組み合わせ。
- 「不特定多数に見せたい」用途（公開サイトの一覧など）は、じぶんシリーズの守備範囲外。
- 「外部の人」が関わらない要件なら、外部共有 SaaS ではなくプラグインの領域。

詳細は [references/products.md](references/products.md)。

## 1b. プラグインで解決できる要件（標準機能の壁に当たったら）

kintone アプリの構築中に次のような要件が出て、JavaScript カスタマイズを書こうとしたら、まず
[references/plugins.md](references/plugins.md) の対応表を見る。代表例:

- 独自ルールの採番 → 自動書式採番。ルックアップでテーブルも取り込む → ルックアップテーブルコピー。
- マスター更新を参照先へ反映 → ルックアップ先自動更新。候補を入力中の値で絞る → ルックアップ絞り込み条件追加。
- 関連レコードの合計・件数を親に持つ → 関連レコード一覧集計（＋トリガー）。
- 一覧からの一括更新・一括空更新・別アプリへの一括転記 → フィールド一括更新／一括空更新／アクション機能拡張。
- Slack/Teams 通知、カードビュー、タブメニュー、郵便番号→住所、ふりがな、西暦和暦、表記ゆれ補正。

提案時のルール: プラグインは **アプリ単位で人がインストール・設定** する（手順は設定画面と問い合わせ窓口に誘導。マニュアルは公開準備中）。
プランは **5 種選択（チョイス）か全部（コンプリート）** の 2 択で、ユーザー数・アプリ数は無制限。
**Zoom Phone 連携などのプレミアムプラグインは別サービス**。カスタマイズ開発は対象外。
プラグインが書き込む先のフィールド（漢数字の出力先、集計値の受け先など）はアプリ設計に含めておく。

## 2. kintone アプリ設計のルール（じぶんシリーズで動くように作る）

kintone アプリを新規に設計・生成するときは、**対応フィールド表** に従うこと。

- 外部ユーザーに **入力させる** フィールドは、文字列一行／複数行／数値／ラジオ／チェックボックス／複数選択／
  ドロップダウン／日付／時刻／日時／添付ファイル／リンク／ルックアップ／テーブル から選ぶ。
- **ユーザー選択・組織選択・グループ選択** は外部ユーザーが入力できない（ページは閲覧のみ、フォームは非対応）。
  外部から「担当者」を選ばせたいなら、ドロップダウンかルックアップに置き換える。
- **リッチエディター・計算** は表示のみ。フォームでは使えない。
- **関連レコード一覧** はページの詳細画面のみで表示できる。一覧・フォームには出ない。
- ルックアップを使うと、コピー先フィールドは自動的に編集不可になる。
- 添付ファイルは 1 ファイル 30MB まで。
- じぶんページで「その人のレコードだけ見せる」場合、**絞り込みキーになるフィールド（メールアドレス・会社名・会員IDなど）を
  kintone アプリ側に必ず持たせる**。ログインユーザーの属性（メールアドレス／名前／カスタムフィールド）と突合する。

製品別の対応表は [references/field-support.md](references/field-support.md)。

## 3. 接続とセットアップの手順（人に案内する）

1. じぶんシリーズのトライアル環境を作る（メールアドレスとパスワードで即時発行。ページは 2 ユーザーまで無期限、
   フォーム／レコードは 30 日間）。
2. **じぶんシリーズ専用の kintone ユーザーを 1 つ作り**、そのアカウントで接続する。kintone の監査ログ上、
   じぶん経由の操作はすべてこの接続ユーザーの操作として記録されるため、個人アカウントを流用しない。
3. 専用ユーザーに、連携する kintone アプリの「レコード閲覧・追加・編集」と（コメント機能を使うなら）コメント権限を付ける。
4. じぶん管理画面で「kintone との接続設定」を行い、連携するアプリを選択して表示・編集項目を設定する。
5. **kintone アプリのフィールドを変更したら、じぶん側アプリの「同期」ボタンを必ず押す**（押さないと新フィールドが出ない・保存に失敗する）。
6. kintone に **IP アドレス制限** を設定している環境では、「IP アドレス制限対応オプション」が必要
   （トライアル中は無料、契約後は月額オプション）。設計時点で確認する。

詳細手順とリンクは [references/setup.md](references/setup.md)。

## 4. 制限事項（設計レビューで必ず確認する）

- kintone API の制限に従う。**同時アクセス 100 件超**でエラーになるため、イベント受付など集中アクセスが
  見込まれるフォームには **ルックアップと添付ファイルを含めない**。
- 1 アプリあたり **1 日 10,000 API リクエスト**。超えると cybozu から警告メール（即停止はしない）。
- Webhook（kintone → じぶんへの通知）は **1 分 60 回** まで。超過分は無視され検知できない。
- フォーム送信が同時アクセス制限に当たった場合、データはじぶんフォーム管理画面にエラーデータとして保存され、
  kintone には入らない・自動返信も送られない。運用手順（CSV 復旧）を顧客に伝える。
- 基盤は Google Firebase（東京リージョン）。中国からの利用は不可の可能性あり。

詳細は [references/limits.md](references/limits.md)。
